# App media

Lyra media comes from two places, and each has one way to shoot it:

| Subject | How |
|---|---|
| **The desktop app**, stills | `pnpm screenshot` (in `apps/lyra`). It launches Electron in a throwaway profile, seeds demo pages and a labeled meeting, and saves `webContents.capturePage()` PNGs. A new shot is a new state in `captureScreenshot` (`src/main/tasks/screenshot.ts`), so it can be retaken after every UI change |
| **The website**, stills and video | The user's Chrome through the **Claude in Chrome extension** (`mcp__claude-in-chrome__*`), [scripts/camera.js](scripts/camera.js), and macOS `screencapture` |

Read the `chrome-browser` skill before the first Chrome step. Do not use the
built-in browser pane for media, and do not use the extension's GIF recorder
(`gif_creator`): GIFs are several times larger than video, look worse, and it
stamps click dots and a watermark on the frame.

**Video of the desktop app itself has no scripted path yet.** Never record
`pnpm dev` with the user's own profile: it opens their real notes folder and
people. If a piece needs real-app video, say so and ask the user how to
proceed.

The website tools:

- **The extension** opens the site, runs camera.js, and makes the one click
  that opens the stage window.
- **camera.js** is pasted into the tab with the extension's `javascript_tool`.
  It opens the stage (a pop-up sized to the frame), and in it draws a cursor,
  plays scripted clicks and typing, eases zoom in and out, hides scrollbars,
  and gives the exact screen rectangle to capture. It only touches that tab
  and the stage, and a reload removes it. Load the file itself (see "Set up
  the shot"); never retype it from memory, or takes drift apart.
- **`screencapture`** (macOS) records that rectangle at the screen's full 2x
  density, **ffmpeg** trims and encodes video, and **cwebp** makes WebP
  (Homebrew's ffmpeg has no WebP encoder).

## The standard

| | Default |
|---|---|
| Frame | Website: **1280×720 CSS px (16:9) at 2x**, so stills are 2560×1440 and video masters 2560×1440. App: the task window (1080×720), at the display's density |
| Theme | Light. Dark only when the piece is about dark mode, and then shot as a pair (`pnpm screenshot --review` already shoots both) |
| Data | The seeded demo pages and meeting (Design review, Team sync notes, Morning journal, Product ideas; Dana, Sam, Alex). Never the user's notes, transcripts, voices or audio |
| Cursor | camera.js cursor (32 px arrow), visible in videos, hidden in stills. It fades out with the content on every zoom and fades back in on the next cursor move, click, or press |
| Camera | Starts on the full frame, zooms to what changes, ends on the full frame |
| Zoom | Eased 900 ms, at most 2x, held at least 1.2 s so it can be read |
| Video length | 5 to 15 s, one idea per clip |
| Frame style | None in the file for the README and website (the page frames it). Social: rounded corners and a soft shadow on a Lyra theme background color |

Change the website frame only when the destination below says so, and then
pass the new size to `__cam.armStage(url, w, h)` so the camera still does the
math.

### Per destination

| Destination | Shot | Size and format | Where it goes |
|---|---|---|---|
| README | The app's main page, light | PNG from `pnpm screenshot` (shown at 920 wide) | `docs/screenshot.png` (the task writes it) |
| Website | Full frame or one element | Stills `.webp` from the 2x capture, under 500 KB, shown with `next/image`; video `.mp4` (H.264) with a `.webp` poster, never GIF or animated WebP | `apps/website/public/<section>/<what-it-shows>.webp` / `.mp4` |
| Release notes (GitHub) | Headline change, still or video | `.png` under 500 KB, or `.mp4` under 10 MB, 1920 wide | Scratchpad; give the file to the user to attach to the release |
| Social | Full frame, or element on the frame background | 1080×1080 or 1920×1080 `.mp4`/`.png` | Scratchpad; give the file to the user |

The website's Open Graph image is generated by `apps/website/app/opengraph-image.tsx`;
change that file, don't capture one.

Name files for what they show (`meeting-transcript.webp`, `dictation.mp4`),
in kebab-case, never `screenshot-1.png`.

## Pre-flight

Run from the repository root. If a check fails, fix what you can and try once
more; if it still fails, stop and tell the user which check failed.

1. `pnpm install` has run (a fresh checkout or worktree has no `node_modules`).
2. `ffmpeg -version` and `cwebp -version` work. If not, ask the user to run `brew install ffmpeg webp`.
3. App stills: nothing else. `pnpm screenshot` uses a throwaway profile and deletes it.
4. Website media: start the site (`pnpm dev:web`, through `preview_start` when it is available) and check `curl -sS -o /dev/null -w '%{http_code}' http://localhost:3100`. Shoot the dev server, not the live site: the production build's content security policy blocks both loading camera.js and the `eval` the stage needs.

## App stills

1. For a shot that already exists (`docs/screenshot.png`, or one of the `--review` states), run:

   ```bash
   pnpm --filter lyra screenshot --review <scratchpad>/review
   ```

   Without `--review` it only rewrites `docs/screenshot.png`.
2. For a new shot, add the state to `captureScreenshot` in `apps/lyra/src/main/tasks/screenshot.ts`: seed what it needs in `seedScreenshotPages`/`seedScreenshotMeeting`, drive the window with `executeJavaScript` and `sendInputEvent` like the existing states, then `save(dir, '<name>-<theme>.png')`. Follow the TypeScript rules and finish with `verify-change`, as for any code change.
3. Read every image back and check it: only the app is in it, the text is sharp, no focus ring, no half-cut text along an edge, demo data only.
4. Crop an element with ffmpeg (`-vf crop=w:h:x:y`) when the destination wants one, then convert: `cwebp -q 85 <in>.png -o <out>.webp`.

## Set up the shot (website)

The extension paints an orange "Claude is working here" border and badge over
every tab in its group while Claude works, and the page cannot hide it. So
nothing is ever recorded in the extension's own tab. camera.js opens a
**stage**: a pop-up window of the same page, sized to the frame, outside the
group, and every take is recorded there.

1. Serve the scripts folder in the background, so the tab can load the file instead of a pasted copy:

   ```bash
   python3 -m http.server 3999 --bind 127.0.0.1 --directory .agents/skills/app-media/scripts
   ```

2. In Chrome, call `tabs_context_mcp`, open a new tab in the group, and navigate to `http://localhost:3100`. Load the camera and arm the stage with `javascript_tool`:

   ```js
   await new Promise((ok, no) => { const s = document.createElement('script'); s.src = 'http://127.0.0.1:3999/camera.js?' + Date.now(); s.onload = ok; s.onerror = () => no(new Error('camera.js did not load')); document.head.appendChild(s); });
   __cam.armStage(); // or __cam.armStage(url, w, h)
   ```

   If the script will not load, paste the whole file into `javascript_tool` instead. After editing camera.js mid-run, close the stage, call `__cam.off()`, and load and arm it again.
3. `left_click` anywhere on the page with the extension. Chrome only lets a click open a pop-up, and the armed click opens the stage instead of reaching the page.
4. Read `__cam.stageResult`: `ok` must be `true` and `dpr` must be `2`. An error string that says the pop-up was blocked means the user must allow pop-ups for the site. On a 1x external display, ask the user to drag the stage to the built-in screen and call `__cam.stage.__cam.viewport()` again.
5. From now on, work in the stage through the tab: `const S = __cam.stage` and `S.__cam`, `S.document`. Client-side navigation keeps the camera; after a full page load (`S.location.href = ...`, the way to reset a shot) wait for it and call `__cam.reinstallStage()`.
6. Find targets. Camera targets take `text=Label` (the last visible control whose text starts with Label, so an open menu wins over the page), a CSS selector, an element, or a `{x, y, w, h}` viewport rectangle for zoom. To pin one control, tag it first: `el.dataset.cam = 'rec'`, then target `[data-cam=rec]`. `S.__cam.find(target)` shows what a target resolves to. Keep `javascript_tool` results short: a result that looks like a URL query string is blocked.
7. The hero animation loops on its own. Scroll the stage to the section, then wait for the moment you want, or reload to restart it, before the take.
8. Close toasts and popovers in the stage. `S.__cam.hide('<selector>')` hides a stray overlay, including the Next.js dev indicator.
9. Rehearse the flow once with `S.__cam.play(steps, { delay: 0 })` and check `S.__cam.scene`, so the take has no wrong turns.
10. Tell the user a take is starting and to leave the computer alone. `screencapture` records the real screen, so the stage must be in front and uncovered. Before every capture, check that Chrome is frontmost (`osascript -e 'tell application "System Events" to name of first process whose frontmost is true'`); if not, `osascript -e 'tell application "Google Chrome" to activate'` and `__cam.stage.focus()`. macOS needs Screen Recording permission for Claude; if a capture is blank or shows another app, ask the user to grant it or bring the stage forward. Never change the setting yourself, and delete any capture that shows anything but the page.

## Website stills

Get the rectangle from the stage, then capture it:

```bash
screencapture -x -R<x,y,w,h> <scratchpad>/still.png
```

- Full frame: `S.__cam.captureRect()`.
- An element in place, with its trigger (a menu under its button): pass a `{x, y, w, h}` rectangle around both, with `24` padding.
- A floating element (toast, popover, side panel): `S.__cam.captureRect(el, 0)`. Padding pulls in half-cut page text around it.

Before capturing, call `S.__cam.hideCursor()` and `S.document.activeElement?.blur()`, or a focus ring is in the shot. Read the image back and check it the same way as app stills, then convert with `cwebp -q 85`.

## Video

A take is one scripted scene that runs inside the stage on its own, so no
extension call is running while it records.

1. **Plan the shot list** before recording: each step, what it clicks or types, and where the camera zooms. Show it to the user when the clip is for a release or the website.
2. Start the scene with one `javascript_tool` call. It returns at once and the scene begins after `delay`:

   ```js
   const S = __cam.stage;
   S.__cam.play([
     { cursor: '<selector>' },                 // glide the cursor
     { click: '<selector>' },                  // press ripple, then a real click
     { wait: 1000 },                           // let the result land
     { zoom: '<selector>', max: 2 },           // ease in on what changed
     { wait: 1500 },                           // hold so it can be read
     { zoomOut: true },                        // ease back to the full frame
     { type: ['<input selector>', 'design'] }, // types at a steady speed
     { type: [null, 'review', 90] },           // into the focused field, 90 ms a key
     { key: 'Enter' },                         // on the focused field
     { hideCursor: true },
   ], { delay: 2500 });
   ```

   Steps take any target from "Set up the shot". End with about 1 s of stillness on the result.
3. Right away, record in the background, a few seconds longer than the scene:

   ```bash
   screencapture -x -v -V<seconds> -R<S.__cam.captureRect()> <scratchpad>/take-<n>.mov
   ```

   Use a new file name for every take: `screencapture` will not overwrite a file.
4. When it ends, check `S.__cam.scene`: `running: false` and `error: null`, and `step` equal to the number of steps. Otherwise fix the step and retake.

Camera rules: zoom when text would be unreadable on a phone, not on every
click. One zoom per idea, at most 2x, held at least 1.2 s. Pause about 1 s on
every result. Never pan while zoomed; zoom out, then in again. Zoom out before
a step that navigates. Never open a menu, popover, or picker while zoomed:
they are positioned from the transformed page and land in the wrong place.
Zoom on the result after the menu closes.

## Edit and encode

1. Read frames from the take (`ffmpeg -i take.mov -vf "fps=1,scale=640:-2,tile=4x3" sheet.png`) to find the start and end of each useful moment.
2. Cut dead air with `trim` and `concat`. Keep the moment a result appears at real speed.
3. Frame it only for social; see "Frame style".
4. Encode H.264 MP4, which plays everywhere including iOS:

   ```bash
   ffmpeg -i <edited>.mov -vf "scale=1920:-2:flags=lanczos,fps=30,format=yuv420p" -c:v libx264 -crf 20 -preset slow -movflags +faststart -an <destination>.mp4
   ```

   Raise `-crf` or shorten the clip if it is over the destination's size limit.
5. Poster, from a full-frame moment near the end that shows the result (not mid-zoom): `ffmpeg -sseof -0.3 -i <destination>.mp4 -frames:v 1 poster.png`, then `cwebp -q 85 poster.png -o <destination>-poster.webp`.
6. Read frames from the start, middle, and end of the final file. Text sharp, demo data only, nothing outside the page, zoom smooth. Retake if not.

## Embed

- README: `docs/screenshot.png` is already linked; keep its `alt` true to what it shows.
- Website: `next/image` with the file's `width` and `height` and real alt text for stills; `<video src poster muted loop playsInline autoPlay>` for clips. Files are served from `public/`, so the site still makes no third-party requests. Run `pnpm --filter web check` and `pnpm --filter web build`. Delete files the page no longer uses.

## Clean up

- Close the stage (`__cam.stage.close()`) and the tabs you opened.
- Stop the servers you started (including the scripts server on 3999) and delete scratch files.
- Commit only the final files (`docs/`, `apps/website/public/`) and any `screenshot.ts` change, one change per commit.
